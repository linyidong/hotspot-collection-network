# 现有方案调研报告

- 项目：Hotspot Collection Network
- 阶段：阶段 2（现有产品、竞品与开源调研）
- 日期：2026-10-19
- 调研方式：联网检索 + 打开原文核对（GitHub API、官方文档、项目 README）
- 标注规则：**【事实】** = 已打开来源核对；**【待验证】** = 只有二手线索或无法核实

---

## 0. 一句话结论

**“采集 + 热点聚合”这件事已经被开源项目做到了很成熟的水平，不需要我们从零造；“把热点加工成可执行的赚钱路径”这件事，没有现成的好方案，必须自己写。**

所以本项目的价值重心应该压在**加工层**，采集层尽量复用。

---

## 1. 市面上有没有同类产品

### 1.1 直接同类（热点聚合 / 舆情监控）

**【事实】** `sansan0/TrendRadar`：63,017 star，Python，GPL-3.0，2025-04 创建，2026-10-15 仍在提交（活跃）。
它已经实现：35 个平台热点聚合 + RSS 订阅 + 关键词筛选 + AI 筛选与翻译 + AI 简报推送（微信/飞书/钉钉/Telegram/邮件/ntfy/bark/slack）+ Docker 部署 + MCP 接入 + 数据本地自持。
—— 换句话说：**“全网热点聚合 + 推送到手机”这个需求，它是现成的。**

**【事实】** `ourongxing/newsnow`：MIT，Node 20+，自托管，30 分钟默认缓存，抓取间隔按源自适应（最小 2 分钟）以防 IP 被封，支持 MCP。
—— 它的**反封策略**（自适应间隔 + 缓存）值得直接借鉴。

### 1.2 邻近产品（跨境选品 / 市场洞察，B 端为主）

**【待验证】** 检索中见到几类商业化产品：妙手 ERP 的「AI 选品专家」、中国制造网的 SourcingAI 3.0、火山引擎「市场洞察 Agent」、合合信息的商业大数据应用。
它们的共同点：面向**企业/卖家**，做选品、找供应商、市场分析，按企业软件收费。
**与我们的差异**：它们回答「卖什么」，我们要回答「**这条热点里谁在缺什么，我下一步该查什么、联系谁**」。而且它们是 SaaS，我们要的是本地、免费、可自己改。

### 1.3 结论

- **没有发现**「输入全球热点 → 输出可执行商机路径」的个人向开源工具。
- 现有工具停在「聚合 + 摘要 + 推送」，没人做「**供需差验证 + 下一步动作**」这一跳。
- 这一跳正是用户的越南手机壳案例里最值钱的部分，也是本项目唯一的技术壁垒（如果做得出来）。

- MIT 项目（china-finance-rss、newsnow）可自由使用、修改、闭源，无负担。
- **GPL-3.0（TrendRadar）**：自己本地用完全没问题；但只要**分发**修改版，就必须开源整个衍生作品。本项目是个人本地工具、不分发，因此可用；如果将来想卖或送人，需要重新评估，**或者只借鉴它的平台接口清单而不复制代码**。

## 3. 数据源可行性实测结论

| 源 | 可行性 | 依据 | 结论 |
|---|---|---|---|
| **财联社** | ✅ 可拿 | china-finance-rss README 明确列出 `/cls/telegraph` 走公开网页端点 | v1 主源 |
| 东方财富 / 同花顺 / 金十 / 华尔街见闻 | ✅ 可拿 | 同上，均为公开端点 | v1 备选，成本几乎为零 |
| **雪球** | ⚠️ 需登录态 | README 明确：雪球封直接 API，必须通过已登录 Chrome 的 CDP 拉取 | v1.1 再接；需本地登录态，稳定性差 |
| **X** | ⚠️ 可拿但成本不透明 | 2026-02 起改为按量付费（credits），单价按 endpoint 在 Developer Console 里看；免费额度只给公共利益类应用；Basic/Pro 固定套餐仍可续 | **v1 先不接**，避免拖慢跑通 |
| **Bloomberg** | ❌ 个人不可行 | 官方页面**不公布任何价格/套餐/配额**，走销售合同（Data License / B-PIPE / Server API），无自助注册 | v1 不做，别在这上面浪费时间 |
| Reddit | 【待验证】 | 有公开 API，但免费额度与条款未核实 | v1.1 评估 |
| YouTube | 【待验证】 | 有 Data API，免费配额未核实 | v1.1 评估 |
| Instagram | ❌ 基本不可行 | 无开放读取接口，抓取违反条款 | 不做 |

**关键提醒（合规）**：以上「公开端点」都是网页接口，不是官方授权的数据 API。个人自用、低频抓取，风险主要在「被源站封 IP」；一旦涉及再分发或商用，就是另一回事。**报告只做技术可行性判断，不构成法律意见。**

## 4. 模型成本实测（按官方现价）

来源：[DeepSeek 官方定价页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)（2026-10-19 打开）

| 模型 | 输入（缓存未命中） | 输入（缓存命中） | 输出 |
|---|---|---|---|
| deepseek-flash | 空闲 1 元 / 高峰 2 元 每百万 tokens | 0.02 / 0.04 元 | 空闲 4 元 / 高峰 8 元 |
| deepseek-v4-pro | 空闲 4.5 元 / 高峰 9 元 | 0.15 / 0.30 元 | 空闲 13.5 元 / 高峰 27 元 |

> 高峰时段 = 工作日 9:00–12:00、14:00–18:00；其余（含周末、法定节假日）为空闲价，**约为高峰的一半**。

**Search / Fetch API**：各 5 元 / 1000 次成功请求（= 0.005 元/次）。**注意：2026-11-01 起在 Harness 里用也会开始计费**。

### 成本推算（按 6 轮/天，不是 8 轮）

修正：8:00–23:00 每 3 小时 = **6 轮/天**（8、11、14、17、20、23 点）。

| 环节 | 单条成本估算 | 每轮量 | 每天 | 每月 |
|---|---|---|---|---|
| 粗筛（flash） | ≈ 0.001 元 | 300 条 | 1.8 元 | ≈ 54 元 |
| 深加工（v4-pro，空闲价） | ≈ 0.05 元 | 10 条 | 3.0 元 | ≈ 90 元 |
| 计划检索（Search API） | 0.005 元/次 | 20 次 | 0.6 元 | ≈ 18 元 |
| **合计** | | | **≈ 5.4 元** | **≈ 162 元** |

**结论：200 元/月的预算足够支撑「300 条粗筛 + 10 条深加工 + 20 次检索」每轮。** 富余约 40 元作为波动缓冲。

**两条省钱要点（会写进架构）：**
1. 静态提示词放在最前面，利用**缓存命中**（0.02 元 vs 1 元，差 50 倍）。
2. 深加工排在**空闲时段**（晚 20 点、23 点、周末），价格减半。

## 5. 用户痛点与竞品空缺

| 用户痛点 | 现有方案覆盖情况 | 空缺 |
|---|---|---|
| 没有停止条件（刷不完） | TrendRadar 有定时推送，但仍是一个流 | 「本轮已看完」的边界感 |
| 没有筛选 | TrendRadar 有关键词 + AI 筛选 | 筛的是「热度」，不是「可赚钱性」 |
| 没有加工 | 都只做摘要/翻译/情感分析 | **无人做「谁在缺什么 + 下一步动作」** |
| 没有沉淀 | 都是推送完就结束 | 无案例库、无复看机制 |

## 6. 可差异化方向（我的判断）

1. **机会四件套**：事实 → 机会类型（6 类枚举）→ 谁在缺什么 → 下一步动作。这是别人没做的，也是唯一值得自己写的部分。
2. **增量叙事**：只讲「这 3 小时新增了什么」，而不是再给一个无限榜单。
3. **可核验**：每条机会必须带「可验证的数字或链接」，否则不许进深加工列表——直接对抗「正确的废话」。
4. **成本可见**：把每次调用的钱摆在界面上，让用户敢开自动。
