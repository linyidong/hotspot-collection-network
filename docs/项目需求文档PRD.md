## 1. 项目概述

一个**运行在用户本机的「商机雷达」**：每 3 小时自动抓取国内外财经/热点信息，先用低成本模型粗筛，再对少量高潜条目做深加工，输出「事实 + 机会类型 + 谁在缺什么 + 下一步动作」四件套，并以监测大屏呈现「最近 3 小时新增」。

**为谁服务**：仅项目所有者本人（单人、本地、无账号体系）。

**为什么做**：用户每天花 2 小时以上在 7 个信息源之间成瘾式浏览，看到的是「发生了什么」，得不到「这跟我赚钱有什么关系」，且笔记散落、从不回看。市面工具（如 TrendRadar，63k star）已把「聚合」做到极致，但**没有一家做「从热点跳到可执行动作」**这一跳。

**产品的唯一价值主张**：把 2 小时的浏览，压缩成 3 分钟的「这一轮有没有值得动手的事」。

## 2. 问题与目标

**用户问题**
1. 没有停止条件：信息无限，只能一直刷。
2. 没有筛选：99% 噪音，少数商机被淹没。
3. 没有加工：只有「发生什么」，没有「谁在缺什么、我该做什么」。
4. 没有沉淀：记了不回看，案例无法复用。

**产品目标**
- 每轮打开后 3 分钟内能判断「这 3 小时有没有值得动手的事」。
- 每条被深加工的条目，必须给出**可执行的下一步**，而不是行业评论。
- 连续使用 5 天后，用户主动查看时长从 2 小时降到 30 分钟以内（自评）。

**成功指标（v1 验收用）**
- 加工质量基准题合格率 ≥ 60%（20 条样本，人工盲评）。
- 单轮全流程耗时 ≤ 5 分钟。
- 月成本 ≤ 200 元。
- 连续 5 天，用户每天至少打开 1 次（不是靠推送，是自己想看）。

**非目标（明确不做）**
- 不做多用户、登录、权限、支付、订阅。
- 不做移动端适配。
- 不做 X / Bloomberg / 雪球接入（v1）。
- 不做代理软件本体（不解析订阅链接、不管节点）。
- 不做自动发邮件 / 自动私信 / 自动下单。
- 不做投资建议、不做荐股。
- 不做真 3D 地球（v1 用轻量版）。

## 3. 用户与场景

| 用户类型 | 场景 | 目标 | 当前痛点 |
|---|---|---|---|
| 本人（唯一用户） | 早上开机后、以及每 3 小时一轮后打开大屏 | 3 分钟内知道「这轮有没有值得动手的事」 | 刷 2 小时仍没结论 |
| 本人 | 看到某条热点觉得有戏，点进详情 | 判断「谁在缺什么、我下一步查什么/联系谁」 | 只能自己脑补，或重开 ChatGPT 从零问 |

| 本人 | 调源、调模型、看花销 | 让它在预算内稳定跑 | 没有成本感知，不敢开自动 |

## 4. 功能范围与优先级

### P0（v1 必须，缺一不可）

| ID | 功能 | 用户价值 | 依赖 | 验收标准 |
|---|---|---|---|---|
| F-001 | 定时调度 | 不用手动触发 | 系统时钟 | 08/11/14/17/20/23 点各触发 1 次；进程重启后错过的轮次补跑 1 次且不重复 |
| F-002 | 多源采集 | 一次看全 | RSS 桥 | 每个源可单独开关；单源超时 20s 不影响其他源；失败源在界面标红并记录原因 |
| F-003 | 去重 | 不重复看同一条 | —— | URL 归一化后完全相同 → 合并；标题相似度 ≥ 0.9 → 合并，保留最早时间 |
| F-004 | 领域粗筛 | 砍掉 90% 噪音 | 低成本模型 | 每条输出 `{is_economic: bool, opportunity_type: 6选1或none, potential: 0-100}`；单条成本 ≤ 0.002 元 |
| F-005 | 限额深加工 | 把噪音变成动作 | 高能力模型 | 每轮最多 N 条（默认 10，可配）；超出进「候选池」不丢弃；单条输出严格四件套 JSON |
| F-006 | 结构化校验 | 防止「正确的废话」 | F-005 | 四件套字段齐全；`next_action.action` 必须含动词且不得是「关注/留意/研究/重视」；`verifiable_data` 至少 1 条；不通过则标记 `rejected` 并记录原因，不进大屏主区 |
| F-007 | 增量视图 | 只看新增，有停止感 | 批次模型 | 大屏分「最近 3 小时新增」与「更早」两区；新增条目标记圆点；批次时间准确到分钟 |
| F-008 | 条目详情 | 看清一条到底说什么 | —— | 展示原文摘要、四件套、原文链接、采集时间、来源、加工模型、本条花费 |
| F-009 | 备忘录 | 沉淀自己的判断 | —— | 可对任意条目写备注；自动保存；重启不丢；支持按机会类型筛选 |
| F-010 | 收藏 | 标记「值得回看」 | —— | 一键收藏/取消；收藏页可搜索标题与备注 |
| F-011 | 模型切换 | 控制成本与质量 | 多 provider 配置 | 粗筛与深加工可分别指定 provider+model；切换后下一轮生效；切换记录写日志 |
| F-012 | 成本与余额 | 敢开自动的前提 | 调用记账 | 每次调用记录 tokens 与金额；可按天/按轮/按模型查看；余额低于阈值时界面提示并可设硬停 |
| F-013 | 源代理分流 | 国内外同时抓，不用手动关代理 | 代理配置 | 每源可配 `direct` / `http://` / `socks5://`；国内源默认 direct，国外源默认 proxy；两者并行不互相阻塞 |

## 5. 关键用户流程

详见 `user-flows.md`。此处只列主干与异常：

**主干**：开机 → 服务自启动 → 08:00 首轮自动跑 → 用户打开大屏 → 看「最近 3 小时新增」→ 点开某条 → 读四件套 → 收藏或写备注 → 关闭页面
**异常 1**：某源失败 → 该源标红，其余照常，日志记原因
**异常 2**：预算逼近上限 → 停止深加工，仅保留粗筛，大屏提示
**异常 3**：加工结果校验不通过 → 该条进 `rejected`，不出现在主区，可在详情页查看原因并手动重试
**异常 4**：手动采集与自动轮次撞车 → 手动请求排队，界面显示「正在跑第 N 轮」

## 6. 页面与交互要求

5 个页面，无第 6 个。每页必须覆盖：加载中、空数据、部分失败、完全失败、正常 五种状态。

| 页面 | 核心区域 | 关键状态与规则 |
|---|---|---|
| **P1 监测大屏** | 中央地球 + 左上「最近 3 小时新增」+ 右上「金价/油价/汇率」+ 下方「更早」 | 首轮未跑：显示引导「点一键采集」；采集中：按钮禁用 + 进度；部分源失败：源名标红；正常：新增条目带圆点 |
| **P2 条目详情** | 标题、来源、时间、原文摘要、四件套、原文链接、备忘录输入、收藏按钮 | 未加工：显示「待深加工」；校验不通过：显示原因 + 重试按钮；正常：四件套分块展示 |
| **P3 备忘录与收藏** | 列表 + 按机会类型筛选 + 搜索框 | 空：引导去大屏；有数据：按时间倒序 |
| **P4 设置** | 源开关、每源代理、模型选择、轮次间隔、每轮深加工限额、预算上限、余额阈值 | 校验失败：代理不可达/Key 缺失时禁用保存并给具体原因 |
| **P5 运行日志与成本** | 每轮摘要表 + 按天/轮/模型的花费 | 预算耗尽：顶部黄色横幅 |

**交互硬规则**

- 任何按钮在请求进行中必须禁用，不得允许重复提交。
- 所有失败必须给出「为什么失败」，禁止只显示「出错了」。
- 不得用弹窗打断（不用 alert/confirm）。

## 7. 业务规则与边界条件

1. **轮次固定 6 轮/天**（08/11/14/17/20/23），间隔可配但默认 3 小时。
2. **深加工限额**：每轮默认 10 条；超出进候选池；候选池上限 200 条，超出按 potential 分淘汰最低的。
3. **预算硬上限**：月预算默认 200 元；剩余 < 10% 时停止深加工；剩余 < 2% 时停止一切模型调用（采集可继续）。
4. **机会类型枚举固定 6 类**，模型不得自创类型；无法归类输出 `none`。
5. **四件套校验不通过 = 不发布**，不降级展示。
6. **原文链接必须保留**，用于人工核查；链接失效不删条目，只标「原文不可达」。
7. **数据保留**：条目保留 90 天，成本流水永久保留（体积小），日志保留 30 天。
8. **并发**：同一时刻只允许一轮采集在跑；手动请求排队。
9. **失败重试**：单条加工失败重试 ≤ 2 次，仍失败则标记 `failed`，不阻塞本轮。
10. **代理**：仅支持标准 HTTP/SOCKS 地址；不实现代理软件、不解析订阅链接、不管节点。
11. **基准题门禁（先提升、后降标）**：
    1. 第一轮合格率 < 60% → **不得降低阈值**，必须先改提示词（可改结构、加约束、加反例、改进筛环节）。
    2. 每轮修改必须记录：改了什么、合格率变化、典型反例。最多迭代 **5 轮**。
    3. 5 轮后仍 < 60%：把「最好的一版」与「全部反例」交给用户，由用户决定：继续迭代 / 调整样本 / 降低阈值。
    4. **降低阈值必须由用户明确同意，并写进 PRD 变更记录**，不得由开发者自行下调。
    5. 降低后的阈值不得低于 40%；低于 40% 时应当质疑产品方向本身，而不是继续调数字。
    6. 60% 的统计口径：20 条样本中，人工判定「我会想点开这条的下一步」的条数 ÷ 20，且不计入被校验层拦下的 `rejected` 条目。

## 8. 数据与权限

**需要保存的数据（本地 SQLite）**

| 表 | 关键字段 | 说明 |
|---|---|---|
| `sources` | id, name, url, enabled, proxy_mode, proxy_url, last_ok_at, last_error | 源配置 |
| `batches` | id, started_at, finished_at, trigger(自动/手动), stats_json | 每轮批次 |
| `items` | id, batch_id, source_id, title, url, url_hash, summary, published_at, region | 原始条目 |
| `analyses` | id, item_id, stage(粗筛/深加工), model, payload_json, status(ok/rejected/failed), cost, created_at | 加工结果 |
| `notes` | id, item_id, content, updated_at | 备忘录 |
| `favorites` | item_id, created_at | 收藏 |
| `llm_calls` | id, batch_id, stage, provider, model, prompt_tokens, completion_tokens, cost, created_at | 成本流水 |
| `config` | key, value | 设置项 |

**权限**：无（单人本机）。**数据归属**：全部本机，不上传第三方（除 LLM 调用必需的文本）。
**敏感数据**：API Key 存在本地环境变量或本地配置文件，**不写入源码、不写入数据库明文、不进日志**。
**删除**：条目可单条删除；清空需二次确认（用页面内确认区，不用弹窗）。

## 10. 非功能要求

- **性能**：单轮全流程 ≤ 5 分钟（300 条粗筛 + 10 条深加工 + 20 次检索）；大屏首屏 ≤ 2 秒。
- **响应式**：仅桌面（≥ 1280px），不做移动端。
- **安全与隐私**：Key 不入库、不入日志、不入仓库；`.env` 加进 `.gitignore`。
- **可维护性**：一条命令启动；改配置走界面，不需要改代码；日志人能看懂。
- **可观测性**：每轮一行摘要；失败必须带原因；成本按调用可追溯。
