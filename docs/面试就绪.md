## 追问预演（答案要点）

1. **「哪个是你写的，哪个是 AI 写的？」**
   → 边界声明（上节）。指一个具体例：`app/sources/gnews.py` 的降级链（Google 不可达 → 360 → 必应）是我定的顺序，代码 AI 写的，我用 `tools/verify_platform_sources.py` 验证过。
2. **「为什么用 SQLite 不用 MySQL？」**
   → 单人本机、3 万条级数据、要能一键拷走（一个 `app.db`）；写并发只有调度器一个进程，上 MySQL 只增加运维成本。若以后多人协作：加 API 层 + WAL 读，再考虑 PostgreSQL。
3. **「补跑怎么保证幂等？」**
   → 三层：批次有唯一键；备份按「日期」判断（同一天重复跑不产生第二份）；写入前查当天记录，同人同天多条会被合并。
4. **「采集数据合规吗？」**
   → README 有固定四句话：只采集公开可访问内容、不涉及登录态与个人信息、不绕过反爬、抓取频率分档。财经源走本地 RSS 桥，榜单为小时/天级。
5. **「7.8 秒/3 页怎么测的？」**
   → `tools/test_amazon_http.py` 单独计时；改 HTTP 直连解析后单次 3 页 7.8 秒（提交 4c8215b），Chrome 只作兜底；整轮快照约 1 分钟（README）。
6. **「如果重做一次，你会改什么？」**
   → 三件：① 建 5 张真实截图的识别回归样例集（RISK-006——LLM 输出质量目前没有自动化保障）；② 给采集结果加"可信度标注"（哪些来自官方源、哪些来自 RSS）；③ 把 20 个源的配置从代码挪进 `data/config.json` 做可视化管理（现在加源要改 registry）。
