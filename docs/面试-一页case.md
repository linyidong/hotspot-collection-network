# 一页 Case ②：热点采集网络

> 用途：面试现场投屏 / 打印带去 / 作为简历附件。
> 讲法：**90 秒讲完这一页**，然后等对方追问——追问点我写在最后一栏。

---

## 一句话

**本机跑的多源热点采集 + LLM 线索加工工具：20 个公开信息源定时抓取，清洗去重入库，规则粗筛 + 模型深加工，最后铺到一块 3D 地球大屏上。**

## 问题（谁在疼）

做跨境选品时，每天要手工翻微博/抖音/百度热搜 + 财联社/东财等财经源 + Amazon 三个榜单，
**大约 2 小时/天**，口径还不统一，最后靠感觉拍。

## 做法

| 要点 | 具体做了什么 |
|---|---|
| **多源接入** | 20 个源分五类：直连 API 4 / 本地 RSS 桥 5 / 新闻 RSS 5 / 热搜 3 / 平台榜单 3；每源独立适配器 + 注册表 |
| **容错降级** | 单源失败不影响整体（标红 + 记失败源）；**Google 新闻不可达自动降级 360 → 必应 RSS**；Amazon 榜单 HTTP 直连优先、Chrome 兜底 |
| **调度幂等** | 定时轮次（3 小时）+ 平台榜单日更；关机/睡眠错过的轮次会补跑；**备份按「日期」判断**，错过 03:30 当天仍补 |
| **可验收** | 自带 `tools/acceptance_run.py` 闭环验收 126 项；`baseline_test.py`（605 行）跑提示词基准题 |
| **成本可控** | LLM 调用有预算上限，每条线索记花费（成本页可追溯） |

## 会被追问的三个点（准备好）

1. **"为什么用 SQLite 不用 MySQL？"** → 单人本机、数据量 3 万条级、要能一键拷走（`data/app.db` 一个文件），迁移成本最低；并发写只有调度器一个进程。
2. **"补跑怎么保证幂等？"** → 备份按日期判断而非按时间；批次有唯一键；重复写入前先查当天记录，同人同天多条会被合并。
3. **"7.8 秒/3 页怎么测的？"** → 用 `tools/test_amazon_http.py` 单独计时；改 HTTP 直连解析后单次 3 页 7.8 秒（见提交 4c8215b），Chrome 只作兜底，整轮快照约 1 分钟（见 README）。
