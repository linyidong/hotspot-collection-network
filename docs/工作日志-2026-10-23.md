## 二、问题清单（现象 → 根因 → 修复 → 验证）

### 1. Mac 启动失败：`错误：需要 Python 3.11 或更高版本`
- **现象**：终端显示"服务启动超时"，日志里反复出现版本错误；日志头部还出现 `D:\...\data\app.db`（Windows 路径）。
- **根因**：
  1. `.venv` 是从 Windows 带过来的（平台相关），里面的 `python` 版本不可用/低于 3.11；
  2. `data/logs/app.log` 也是从 Windows 拷来的旧日志，混着历史记录，容易误判；
  3. `/api/health` 里同步重启 RS​​S 桥（15–30 秒），启动脚本 30 秒超时；
  4. 桥子进程 stdout 用 PIPE 但没人读，写满后桥"存在但不响应"。
- **修复**：
  - `启动.command` 校验系统 `python3 >= 3.11`；`.venv` 不可用自动重建；依赖导入自检；等待上限 90 秒；打印实际解释器；
  - `/api/health` 的桥自愈改后台线程（实测单次 2.2s → **135ms**）；
  - `app/bridge.py` 增加 `_drain` 线程持续消费子进程输出；
  - `run.py` 日志超过 5MB 轮转为 `app.log.1`。
- **验证**：Windows 启动 4.1 秒、health 135ms、桥 ok。
- **迁移原则**：只拷代码 + `data/app.db` + `.env`，**不要拷 `.venv` 和 `data/logs`**。

### 2. RSS 桥端口写死 8053
- **现象**：端口被占用时桥起不来，5 个桥源（财联社/东财/同花顺/金十/见闻RSS）全部 502。
- **修复**：
  - 端口自动分配：优先 `RSS_BRIDGE_PORT`(8053)，被占用依次 +1 到 +20，全满由系统随机；
  - `collect` 使用运行时真实端口（`bridge.port`），不再读配置值；
  - 启动写 `data/logs/bridge.pid`；
  - Windows 端口探测改用 `SO_EXCLUSIVEADDRUSE`（`SO_REUSEADDR` 在 Windows 允许抢绑已监听端口，会误判空闲）。
- **验证**：占用 8053 后自动用 **8054**，`/cls/telegraph` HTTP 200 / 50 条；8053 空闲时回到 8053。

### 3. 停止脚本危险写法（误杀执行脚本的 shell）
- **现象**：用"命令行包含 china-finance-rss 就 kill"做兜底，把正在执行脚本的 shell 自己也杀掉了，宿主会话中断。
- **修复**：改为 **pid 文件 + 端口扫描 8053–8075**；Mac `停止.command` 同样按 `bridge.pid`/`app.pid` + 端口。
- **验证**：停止后 9000/8053/8054 全部释放，pid 文件清理。

### 4. 三列看板：收起后不复原两列
- **根因**：`ensureCol3(on)` 只在"无可见子面板"时收；`collapseCol3IfEmpty(force)` 传了 force 但函数不接收，点「收起第三侧」无效。
- **修复**：`ensureCol3(on, force)`；force 时把 `.col3` 全部面板（含 removed）搬回左列、权重重置、清空 `#cen` 内联宽度/边距、落盘；三条调用路径（按钮/拖走/加载自愈）统一。
- **验证**：`three=false`、无 `.col3`、8 块面板全可见、两列高度差 0px、权重复原。

### 5. 三列看板：宽屏覆盖地球
- **现象**：1920 宽三列时想覆盖地球 333px；用户要求宽屏不覆盖、窄屏覆盖。
- **修复**：断点 1800px；宽屏三列 `#grid` 取消 absolute、占真实宽度（clamp 46vw），`#cen` flex:1 自适应，地球比例由相机自适应；窄屏保留浮层覆盖并锁定地球宽度；`ResizeObserver` 跨断点自动切换。
- **验证**：1920 重叠 **0px**（地球右缘 1008 ≤ 面板左缘 1018）；1440 重叠 246px 且地球 508×713 不变形。

### 6. 三列看板：窄屏跨断点往返后地球变窄
- **现象**：1440→1920→1440 后地球从 508 变 469。
- **修复**：两列宽度缓存 `CEN2COL`（按 `innerWidth`，最近视口匹配 ≤100px），窄屏三列优先用缓存锁定宽度。
- **验证**：往返后仍 508（差 0px）。

### 7. 三列看板：「×」移除最后一块不自动收起（Mac 各浏览器复现）
- **根因**：`×` 路径只加 `removed` + `save()`，从不调用 `collapseCol3IfEmpty()`。
- **修复**：`__panelHide()` 延迟调用收起；`#grid` 上挂 **MutationObserver**（`.col3` 子节点/class，50ms 防抖，收起前 disconnect 防自循环）覆盖所有变空路径；三个脚本加 `?v=20261023` 防浏览器缓存旧 JS。
- **验证**：`[PASS] × 移除最后一块自动收起 three=False col3=False`（1920/1440 各一条），被移除面板仍可恢复。

### 8. 页面 console 报 favicon 404
- **修复**：5 个页面加内联 SVG 地球图标（data URI），不再请求 `/favicon.ico`。
- **验证**：多分辨率扫描「无控制台错误」全 PASS。

### 9. Amazon 反爬导致榜单源全挂
- **现象**：Amazon 页面返回空，快照被刷新成 `pages: {}`，3 个榜单源报错（体检 17/20）。
- **修复**：刷新失败**保留上一份快照**（标记 stale）并记录错误；失败后用更接近真实浏览器的参数重试一次；新增 `tools/rebuild_snapshot.py` 从数据库历史条目重建。
- **验证**：从批次 #61 恢复 3 榜单 / 60 条，体检 **20/20**。

### 10. 采集段耗时冒到 113 秒（超 90 秒验收线）
- **根因**：Google 连接超时，重试 3 次 + 退避把采集拖长。
- **修复**：gnews 连接超时单独 8 秒、重试 3→2 次、退避固定 2 秒、必应最多 2 个关键词变体。
- **验证**：批次 #62 采集段 **8.0 秒**、20/20 源、679 条。

### 11. Trae 协作问题（超时/发送失败）
- **现象**：Trae 任务跑到一半超时；`TRAE_SEND_FAILED`；任务长时间 queued。
- **处置**：
  - 重启 Trae（`Stop-Process` 全部 Trae → 重新启动，CDP 9333 约 10 秒就绪）；
  - 把大任务拆成 3 个小任务（收起复原 / 宽屏断点 / 窄屏宽度缓存），每个限定改动文件与 10–15 分钟时限；
  - DSH 全程独立验收（脚本量测，不采信 RESULT.md 自述）。
