# 项目复杂度判断与原型分流

- 项目：Hotspot Collection Network
- 阶段：阶段 3
- 日期：2026-10-19
- 判断时点：闸门 A（访谈 + 调研完成后初判）。**闸门 B 在 PRD 与用户流程草稿完成后复核。**

---

## 1. 复杂度评分

| 维度 | 分值 | 判断理由 |
|---|---|---|
| 页面/用户流程复杂度 | **2** | 大屏 + 条目详情 + 备忘录/收藏 + 设置（源/模型/代理）+ 日志，共 5 个界面；且状态复杂（本轮/更早、候选池、采集进行中、失败态） |
| 用户/角色/权限 | **0** | 单人、无登录、无权限 |
| 数据持久化/迁移 | **1** | 本地 SQLite 即可，**9 张表**（源、批次、条目、加工结果、笔记、收藏、成本流水、配置、心跳），无迁移历史包袱 |
| 外部集成 | **2** | RSS 桥、LLM API（至少 2 个模型可切）、行情接口、代理、定时调度，五类外部依赖 |
| 业务风险 | **1** | 个人工具，错误代价低；但涉及**真实花钱**与**合规边界**，不能算 0 |
| 需求不确定性 | **1** | 目标与范围清晰；不确定的是**加工质量能否达标**（不是需求本身不清楚） |
| **合计** | **7** | |

> 按模板：4–7 分为标准路径，8 分以上或存在单项 2 分高风险项走复杂路径。本项目 **7 分，压线**。

## 2. 但有两处信号指向"更严格"

模板里写明「**AI 多步骤工作流**」属于复杂路径的典型特征。本项目恰好是：

```
定时触发 → 多源抓取 → 去重 → 领域粗筛 → 限额深加工 → 结构化校验 → 增量落库 → 大屏呈现
```

这是一条 8 环节的 AI 流水线，**任何一环静默失败，整条链路都在"假装正常"**——这比页面多不多危险得多。

因此我的判定不按 7 分机械落"标准"，而是：

> **路径判定：标准路径（偏严格），按"准复杂"标准管理。**

具体表现：流程与数据模型按复杂路径准备，页面视觉按标准路径处理（不做完整交互原型）。

## 3. 路径决策

| 项 | 结论 |
|---|---|
| **判定路径** | **标准路径（偏严格）** |
| **是否需要交互原型** | **部分需要**——不做整套 Figma 交互原型，但**必须先有一版大屏视觉稿**再进入编码 |
| 不做原型如何验证交互 | 用一版**静态 HTML 大屏稿**（真实排版 + 假数据）代替点击原型，你在浏览器里看一遍，确认布局、分区、信息密度；改起来 30 分钟一版 |
| 为什么不用完整原型 | 单页大屏的信息密度问题，静态稿就能暴露；用 Figma 做完整交互，成本大于收益 |
| 高风险项 | ① 加工质量（唯一生死项）② 数据源稳定 ③ 成本失控 |
| 后续重新评估触发条件 | 出现以下任一情况，升级为复杂路径：<br>• 开始做多用户/账号/支付<br>• 接入需要登录态的源（雪球、X）<br>• 增加自动对外发送（邮件/私信）<br>• 加工链路超过 10 个环节 |

## 4. v1 页面清单（供阶段 4 PRD 使用）

| # | 页面 | 核心内容 | 关键状态 |
|---|---|---|---|
| P1 | 监测大屏 | 中央地球（热点打点）+ 左上「最近 3 小时新增」+ 右上「数据波动（金价/油价/汇率）」+ 下方「更早」 | 空（首轮未跑）/ 采集中（进度）/ 部分源失败（标红）/ 正常 |

| P3 | 备忘录与收藏 | 列表 + 按机会类型筛选 + 搜索 | 空 / 有数据 |
| P4 | 设置 | 源开关 + 每源直连/代理 + 模型选择（粗筛/深加工）+ 轮次间隔 + 每轮限额 | 校验失败（代理不可用/Key 缺失） |
| P5 | 运行日志与成本 | 每轮：抓取数 / 筛出数 / 深加工数 / 花费 / 失败源；余额看板 | 正常 / 预算耗尽（停止深加工并提示） |

> 共 5 个页面。没有第 6 个。

## 6. 我的建议（不替用户决定）

先做**加工质量基准题**，再做界面。

理由：加工质量不过关，大屏做得再漂亮也只是个更贵的新闻网站。基准题成本约 1 元、半天时间，却能提前排除最大的死亡风险。

如果你的排序是「先看到大屏才有动力」，也成立——那就把静态视觉稿排在前面，但**基准题不能跳过**，只能往后挪。
