## 二、这个项目到底在做什么（业务逻辑）

### 2.1 产品定位

单人、本机、无账号的「商机雷达」：每 3 小时扫一遍国内外财经/热点，用便宜模型粗筛，用贵模型把少量高潜条目加工成**可执行的线索卡**，让用户 3 分钟内判断「这一轮有没有值得动手的事」。

**唯一价值主张**：把 2 小时成瘾式浏览，压缩成 3 分钟的「有没有值得动手的事」。

**用户能力边界（写进提示词的硬约束）**：0 本金、无资质、1 人、个人身份、每天 4–6 小时。任何需要牌照/垫资/团队/企业主体的方案，必须被能力闸拦下。

### 2.2 主链路（一次轮次）

```
20 个源并行抓取（单源 20s 超时、失败隔离、桥自愈）
  → 全部条目落 items（记录 batch_id、region）
  → 去重：URL 归一化 + 批内标题相似度≥0.9 + 跨批次 7 天 url_hash
  → 事件去重（LLM 把同一件事的多篇报道合并，最多 60 条）
  → 粗筛（deepseek-flash，并发 6）：is_economic / anchors / potential
  → 候选排序：potential 降序 + 每品类上限 3 → 取前 10 条
  → 深加工（deepseek-v4-pro）：输出线索卡 JSON
  → 12 条校验（r1–r12，含 r11 能力闸、r12 行业枚举、r8 认输）
  → ok 进大屏主区；rejected 进「已排除」；failed 重试≤2 后标记
  → 每次模型调用立即写 llm_calls（tokens/单价/金额/batch/stage/model）
  → 本轮汇总写 batches.stats_json + 预算熔断判定
```

最近一轮（#63）的真实数字：抓取 588 → 去重后 340 → 粗筛 ok 214 → 事件合并 80 → 候选 10 → 深加工 ok 7 / rejected 3（r11 拦 1）→ 花费 ¥0.643 → 206.6 秒。

### 2.4 调度与日常运维

- 固定 6 轮：08/11/14/17/20/23；错过 2 小时内唤醒会补跑（`misfire_grace_time=7200`）。
- 启动补跑：默认最多 1 轮（可配 0–5），遇失败/无源/硬停即停。
- 心跳每 5 分钟一条，调度审计用「在线区间」口径，关机/睡眠不算漏轮。
- 每日 03:30 备份（保留 7 份）、04:05 清理、05:00 刷新 Amazon 榜单快照。
- 清理：条目按 `item_retention_days`（默认 90 天）删除，连带 analyses/notes/favorites；`llm_calls` 保留 30 天；心跳 30 天。

### 2.5 页面与数据

- 5 个页面：大屏 `/`、详情 `/static/detail.html`、备忘录收藏 `/static/notes.html`、设置 `/static/settings.html`、成本/日志 `/static/cost.html`。
- 大屏 8 个面板：新增（3 小时）/ A·B 级 / S1 选品 / S3 交易结构 / 更早 / 已排除 / 平台信号 / AI 建议解析；中央是 three.js 3D 地球（昼夜、云层、飞线、光点）。
- 9 张表：items、batches、analyses、sources、notes、favorites、llm_calls、config、heartbeats（config 实际 0 行，业务配置走 `data/config.json`）。

### 5.2 规则/数据冲突（必须由用户拍板，不能静默选一边）

1. **`llm_calls` 保留期**：PRD §7 规则 7 写「成本流水**永久保留**（体积小）」；`app/cleanup.py` 实际保留 **30 天**，验收 T-131 还把「30 天前调用被清理」判为通过。删掉的是账本，和 AGENTS「成本是硬约束、对不上账就是 bug」直接冲突。
2. **条目过期后的备注/收藏**：PRD 数据保留只说条目 90 天；user-flows 流程 3 写「条目已过期：显示仅保留你的备注」；实际 `cleanup.run` 把 notes/favorites 跟 items 一起删。用户的判断会随条目一起消失。
3. **手动采集撞车**：PRD §7 规则 8 写「手动请求**排队**」；实际 `/api/run` 返回 409、不排队；user-flows 又写「不排队、不打断」。三处口径不一致。
4. **真 3D 地球**：PRD §2 非目标写「不做真 3D 地球」；实际已是 three.js WebGL（昼夜/云层/飞线）。这是已被用户默认接受的范围变更，但文档没改。
5. **6 类机会类型**：PRD F-004 要求粗筛输出 `opportunity_type` 6 选 1；实际粗筛只输出 `is_economic/anchors/potential`，6 类只存在于提示词说明和 `stage/money.form/signal` 里，没有字段，也没有校验。
6. **候选池 200 上限 vs 不丢弃**：PRD 两处都写「超出进候选池不丢弃」，同时又说「上限 200、超出淘汰最低 potential」；实际两个都没做。
