# 用户能力画像（capability profile）

- 版本：v0.1（用户确认：暂时有效）
- 日期：2026-10-19
- 用途：**能力闸**的判定依据。任何线索卡的动作，只要突破这份画像，就判不合格。
- 重要：这份画像是**可配置**的。用户后续可能有本金、有资质，只需改这个文件，不必改提示词。

---

## 1. 当前边界（v0.1）

| 维度 | 当前值 | 含义 |
|---|---|---|
| 启动资金 | **0 元** | 只能一件代发 / 先单后货 / 零成本数字品 |
| 资质牌照 | **无** | 不能做：律所、基金销售、报关行、融资顾问、医疗器械、食品经营、进出口代理 |
| 团队 | **1 人** | 不能承接需要分工、驻场、7×24 响应的活 |
| 每天可投入 | **4–6 小时** | 超过这个强度的方案判 C |
| 语言 | 中文为主，**可用 AI 翻译** | 外语不是障碍，但不能要求“英语流利谈判” |
| 技术 | 会照教程装环境、跑命令 | 不能要求写代码、搭服务器、做 App |
| 身份 | 个人，**非公司主体** | 不能签需要企业资质、开票资质、对公账户的合同 |
| 可执行的通用动作 | 查公开数据、注册平台账号、发邮件/私信、上架商品、找工厂询价、找货代询价、做文档/表格/资料包 | —— |

## 2. 能力闸规则（写进校验）

每条线索卡必须带 `feasibility` 字段：

```json
{
  "feasibility": {
    "needs_license": false,
    "needs_capital": false,
    "needs_team": false,
    "needs_identity": false,
    "reason": "一句话说明为什么在能力范围内"
  }
}
```

**任一项为 `true` → 判 `rejected`，原因 `r11_超出个人能力`。**

| 字段 | 什么时候为 true |
|---|---|
| `needs_license` | 需要牌照/资质/备案（法律服务、基金销售、报关、医疗、食品、进出口代理） |
| `needs_capital` | 需要先垫钱（囤货、开信用证、保证金、买设备/库存） |
| `needs_team` | 需要多人分工、驻场、持续值班 |
| `needs_identity` | 需要企业主体、对公账户、行业身份（如“以基金公司名义”“以律所名义”） |

## 3. 典型误判（v0.4 实测抓到的）

这些是模型在**没有能力闸**时给出的“机会”，全部越界：

| 线索 | 模型建议 | 越界点 |
|---|---|---|
| 主动 ETF 获批 | 联系大成基金渠道部谈海外代销 | `needs_license` + `needs_identity` |
| 科创债政策 | 联系中证指数公司合作开发指数产品 | `needs_license` + `needs_identity` |
| 宁德时代回购 | 介绍宁德时代电池给海外车厂赚佣金 | `needs_team` + `needs_identity` |
| 海光信息业绩 | 申请国产高端芯片代理分销资质 | `needs_license` + `needs_capital` |

**共同特征：把“我”默认成了任何角色。** 能力闸就是防止这一点。

## 4. 升级路径（用户将来改这里）

当用户具备以下任一条时，修改第 1 节对应行，并重跑基准题：

- 有启动资金（例如 5 万元）→ `needs_capital` 的阈值改为“≤5 万可接受”
- 有营业执照 → `needs_identity` 放宽为 false（但仍需 `needs_license` 的专项资质）
- 有团队 → `needs_team` 放宽

**注意**：能力放宽后，A/B 级线索会变多，但**风险也变大**。建议每次放宽后重跑一次基准题，观察“越界型线索”是否重新混进来。
