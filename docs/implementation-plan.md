## T0：加工质量基准题（**先做，不建界面**）

**目标**：用 20 条真实热点验证「四件套」是否达到可执行水平。

**做什么**
1. `prompts/coarse.md`、`prompts/deep.md` 初版。
2. `tools/baseline_test.py`：读 `data/baseline/samples.jsonl`（20 条），跑完整加工链，输出 `data/baseline/report.md`。
3. 人工盲评：逐条标记「会不会想点开下一步」。
4. 不达标 → 改提示词 → 重跑，最多 5 轮，每轮记入 `docs/prompt-log.md`。

**验收标准**
- 合格率 ≥ 60%（20 条中 ≥12 条被用户标「想点开」）。
- 越南手机壳类案例能被还原为：需求存在 + 可用进出口数据验证 + 下一步指明查什么数据/联系谁。
- 零「正确的废话」进入 `ok`（出现即算失败项，需修）。

**明确不做**：不写界面、不建数据库、不做调度。只有脚本 + 提示词。

## T1：静态大屏稿

**目标**：在写任何产品代码前，确认布局与信息密度。

**做什么**
1. `static/mockup.html`：单文件，内嵌假数据，无后端。
2. 包含：地球区、3 小时新增区、指标卡（金价/油价/汇率）、更早区。
3. 至少两版布局供选择（信息密度高/低）。

**验收标准**
- 用户打开文件即可看到完整大屏，无需启动服务。
- 用户能指出「哪块该放大、哪块多余」。
- 页面在 1280×720 与 1920×1080 下都不出现横向滚动。

---

## T2：项目骨架与配置

**做什么**
1. `run.py` 一条命令启动（含 Python 版本检查、缺依赖时给中文提示）。
2. `app/config.py`：读 `.env` + `data/config.json`，缺必填项给出明确错误。
3. `app/db.py`：建 8 张表、WAL、幂等建表。
4. 空壳页面能打开，`/api/health` 返回 ok。

**验收标准**
- 全新机器：`pip install -r requirements.txt` 后 `python run.py` 能起来。
- 缺 `DEEPSEEK_API_KEY` 时，启动不崩溃，页面显示「未配置密钥」的具体指引。
- 重复启动不会报端口占用却不解释。

---

## T3：采集层

**做什么**
1. 启动 `china-finance-rss` 子进程（8053），失败时给出中文原因。
2. `sources/base.py` 定义统一接口：`fetch() -> list[RawItem]`。
3. 实现 5 个国内源（财联社/东财/同花顺/金十/华尔街见闻）。
4. 每源超时 20s、失败隔离、写入 `sources.last_error`。
5. 源代理模式（direct/proxy），并行抓取。

**验收标准**
- 单源失败时其他源仍能出结果，界面/日志能看到哪个源失败及原因。
- 单轮抓取 5 源总耗时 ≤ 90 秒。
- 关闭全部源时，本轮明确标记「无可用源」，不产生空成功。

---

## T4：去重 + 粗筛

**做什么**
1. `dedup.py`：URL 归一化（去 utm/去锚点）+ 标题相似度（≥0.9 合并）。
2. `llm/coarse.py`：单条判定 `is_economic` / `opportunity_type` / `potential`。
3. `cost.py`：每次调用立即记账。
4. 粗筛失败条目标 `failed`，不静默丢弃。

**验收标准**
- 同一 URL 重复抓取只保留 1 条。
- 300 条粗筛成本 ≤ 0.5 元。
- 粗筛结果与人工抽查 20 条的一致率 ≥ 80%（用户抽检）。

---

## T5：深加工 + 校验

**做什么**
1. `llm/deep.py`：按 `prompts/deep.md` 输出严格 JSON（四件套）。
2. `validate.py`：实现架构文档 3.3 的 6 条规则。
3. 不通过 → `rejected` + 原因；重试 ≤2 次。
4. 超出限额 → 候选池；**候选池上限 200 条，超出按 potential 淘汰最低的（本任务实现上限与淘汰逻辑，v1 无独立页面入口，仅在日志与详情页显示「候选池 N 条」）**。

**验收标准**
- 四件套字段齐全率 100%（不合格的必须进 rejected，不能缺字段进 ok）。
- 「下一步」只写「关注/留意」的条目 100% 被拦下。
- 单条深加工成本 ≤ 0.08 元。

---

## T6：调度 + 手动采集 + 批次

**做什么**
1. `scheduler.py`：08/11/14/17/20/23 触发；启动时补跑错过的最近一轮。
2. `orchestrator.py`：串联 T3→T5，全局互斥锁（同一时刻只跑一轮）。
3. `/api/run`：手动触发；有轮次在跑返回 409。
4. 错误被捕获时产生 `degraded` 批次并给出原因，不允许静默空结果。

**验收标准**
- 连续跑 3 轮，`batches` 记录完整，统计数字与实际一致。
- 手动与自动撞车时，手动请求被正确拒绝且提示清楚。
- 人为制造某一环节异常，批次状态为 `degraded` 并带原因。

## T7：大屏 P1

**做什么**
1. 按 T1 确认的布局实现 `index.html`。
2. Canvas 地球：贴图旋转 + 按地域打点（无地域信息不打点）。
3. 「最近 3 小时新增」/「更早」分区；新增标记。
4. 指标卡（金价/油价/汇率）；行情失败降级为「暂不可用」，不崩页面。
5. 采集中进度反馈；一键采集按钮状态机。

**验收标准**
- 首屏 ≤ 2 秒（本地）。
- 采集中按钮禁用并有进度文案。
- 无新增时文案为正向（「这 3 小时没有值得看的新增」），不是报错样式。
- 地球在 1280 宽度下不遮挡文字区。

---

## T8：详情 P2 + 备忘/收藏 P3

**做什么**
1. 详情页：四件套分块、原文链接、来源、时间、模型、本条花费。
2. `rejected` 条目展示原因 + 重试按钮。
3. 备注自动保存（失焦即存）；收藏一键切换。
4. 备忘/收藏页：筛选 + 搜索。

**验收标准**
- 备注保存后刷新页面仍在。
- 重启服务后备注与收藏不丢。
- 收藏取消有页面内二次确认（无弹窗）。

---

## T9：设置 P4 + 代理分流

**做什么**
1. 源开关、每源代理、模型选择（粗筛/深加工）、轮次间隔、每轮限额、预算上限。
2. 保存前校验：代理连通、Key 存在。
3. `/api/settings/test-proxy`。

**验收标准**
- 代理填错时保存被拒，提示具体地址与错误原因。
- 修改模型后下一轮生效，且 `llm_calls` 里记录的是新模型。
- 修改限额后本轮立即按新限额执行。

---

## T10：日志与成本 P5 + 熔断

**做什么**
1. 日志页：每轮摘要（抓取/去重/粗筛/深加工/失败源/花费/耗时）。
2. 成本页：按天/按轮/按模型。
3. 熔断：剩余 <10% 停深加工；<2% 停所有模型调用；顶部横幅提示。
4. **数据清理：条目保留 90 天（PRD §7 规则 7）、日志保留 30 天、候选池按上限淘汰（T5 已实现，本任务加定时触发）。**

**验收标准**
- 把预算上限改成极小值，下一轮正确熔断且提示清楚。
- 成本页合计与 `llm_calls` 求和一致（误差 0）。
- 日志保留 30 天，超出自动清理。

---

## T11：验收与交付

**做什么**
1. 按 `acceptance-test-plan.md` 逐项跑，区分通过/未通过/未执行/未实现。
2. README：安装、启动、常见错误、如何换源、如何改提示词。
3. 每日自动备份数据库，保留 7 份。
4. `progress.md` 收尾。

**验收标准**
- 在一台没装过 Python 的机器上，照 README 能跑起来（用户实操验证）。
- 验收表中无「未执行」项留在核心功能上。
- 备份文件可恢复（演练一次）。

---

## 排期原则

- **T0 不过，T1 不做；T1 不确认，T2 不做。** 这两道闸不许跳。
- 每个任务完成后更新 `progress.md`，并由用户在验收摘要上签字（对话确认即可）。
- 任何任务超出原定范围，先停下来说明，不擅自扩张。
