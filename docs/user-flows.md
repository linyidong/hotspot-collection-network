## 一、核心用户流程

### 流程 1：每轮查看（最高频，每天 6 次）

- **触发入口**：用户打开浏览器（书签）→ 大屏首页；或收到「本轮已完成」的页面角标提示
- **用户目标**：3 分钟内判断「这 3 小时有没有值得动手的事」
- **前置条件**：服务已启动；至少完成 1 轮采集
- **主成功路径**：
  1. 打开大屏，视线落在「最近 3 小时新增」区
  2. 扫一眼条目数（0 条 → 直接关闭，用时 < 10 秒）
  3. 有值得看的条目 → 点开详情
  4. 读四件套：事实 / 机会类型 / 谁在缺什么 / 下一步
  5. 判断：收藏、写备注、或直接关掉
  6. 关闭页面
- **异常/替代路径**：
  - 网络或服务失败：整页显示「服务未启动」+ 启动命令提示（用户能照抄）
  - 部分源失败：该源名标红，其余正常展示，不阻塞
  - 没有数据（首轮未跑）：显示「还没跑过，点一键采集」
  - 新增为 0：显示「这 3 小时没有值得看的新增」——**这是正反馈，不是错误**
- **流程完成标志**：用户关闭页面。理想状态下 30% 的轮次在 10 秒内关闭

### 流程 2：深挖一条（中频）

- **触发入口**：大屏中点击某条目
- **用户目标**：判断「这条到底有没有搞头、我下一步干什么」
- **前置条件**：该条目已完成深加工
- **主成功路径**：
  1. 进入详情页
  2. 读「谁在缺什么」——确认是否成立
  3. 读「下一步」——判断自己愿不愿意做（查数据 / 联系谁）
  4. 点原文链接核对事实
  5. 写一句备注（例如「可查越南海关 HS3926 数据」）
  6. 收藏
- **异常/替代路径**：
  - 未加工：显示「待深加工」+ 手动加工按钮
  - 校验不通过：显示未通过原因（例如「下一步只写了『关注』」）+ 重试按钮
  - 原文不可达：标「原文链接失效」，保留摘要与四件套
- **流程完成标志**：产生一条备注或一次收藏

### 流程 3：沉淀复用（低频，每周）

- **触发入口**：进入「备忘录与收藏」页
- **用户目标**：找回上周记下的东西，判断哪些还能做
- **前置条件**：已有备忘录或收藏
- **主成功路径**：
  1. 按机会类型筛选（如只看「跨境贸易差价」）
  2. 搜索关键词
  3. 打开条目回看四件套与自己的备注
  4. 决定：继续跟进 / 放弃并取消收藏
- **异常/替代路径**：
  - 空：引导回大屏
  - 条目已被清理（超 90 天）：显示「原文条目已过期，仅保留你的备注」
- **流程完成标志**：至少一条被重新打开并产生动作

### 流程 4：调参（低频，出问题时）

- **触发入口**：设置页
- **用户目标**：让它在预算内稳定跑，并修掉失败源
- **前置条件**：有配置权限（本机唯一用户）
- **主成功路径**：
  1. 看「运行日志与成本」定位问题（哪一轮、哪个源、花了多少）
  2. 进设置页，关闭故障源或改代理
  3. 调整粗筛/深加工模型
  4. 调整每轮深加工限额与预算上限
  5. 保存 → 系统校验（代理可达、Key 存在）→ 生效于下一轮
- **异常/替代路径**：
  - 代理不可达：保存被拒，提示「代理 127.0.0.1:7890 连接失败」
  - Key 缺失：保存被拒并指向 `.env` 文件位置
  - 预算已达上限：允许保存，但提示「保存后本轮只跑粗筛」
- **流程完成标志**：下一轮运行成功且失败源恢复

### 流程 5：手动补采（随时）

- **触发入口**：大屏「一键采集」按钮
- **用户目标**：立刻看一次最新情况
- **前置条件**：无轮次在进行
- **主成功路径**：
  1. 点击按钮 → 按钮禁用，显示进度（抓取中 → 粗筛中 → 深加工中）
  2. 5 分钟内完成 → 新增条目进入「最近 3 小时新增」区
- **异常/替代路径**：
  - 已有轮次在跑：按钮置灰并显示「正在跑第 N 轮」，不排队、不打断
  - 预算不足：提示「预算不足，仅跑粗筛」，仍可执行
  - 全部源失败：显示失败原因清单，不产生空批次
- **流程完成标志**：本轮批次写入并可见

### 流程 6：加工质量基准题（一次性，开发期）

- **触发入口**：命令行脚本（不做界面）
- **用户目标**：验证四件套是否达到「可执行」水平
- **前置条件**：有 LLM Key；准备 20 条真实热点样本
- **主成功路径**：
  1. 运行脚本，输入 20 条样本
  2. 输出 20 份四件套 + 每条花费
  3. 用户盲评：这条我会不会想点开「下一步」
  4. 统计合格率
- **异常/替代路径**：
  - 合格率 < 60%：**停止界面开发**，改提示词重测
  - 出现「正确的废话」：记录原文，作为反例入库
- **流程完成标志**：合格率 ≥ 60%，且越南手机壳类案例能被正确还原

## 二、页面清单

| 页面 ID | 页面名称 | 谁能访问 | 页面目标 | 主要操作 | 数据来源 | 状态/错误 |
|---|---|---|---|---|---|---|
| P-001 | 监测大屏 | 本机用户 | 3 分钟看清本轮 | 点条目、一键采集、切换增量/更早 | `batches`、`items`、`analyses`、行情 | 首轮未跑 / 采集中 / 部分源失败 / 无新增 / 正常 |
| P-002 | 条目详情 | 本机用户 | 判断一条有没有搞头 | 读四件套、开原文、写备注、收藏、重试加工 | `items`、`analyses`、`notes` | 待深加工 / 校验未通过 / 加工失败 / 原文不可达 / 正常 |
| P-003 | 备忘录与收藏 | 本机用户 | 找回并复用 | 筛选、搜索、取消收藏 | `notes`、`favorites` | 空 / 条目过期 / 正常 |
| P-004 | 设置 | 本机用户 | 调源、调模型、控成本 | 开关源、配代理、选模型、改限额、设预算 | `sources`、`config` | 校验失败（代理/Key）/ 正常 |
| P-005 | 运行日志与成本 | 本机用户 | 定位问题、看花销 | 按天/轮/模型查看、查看失败原因 | `batches`、`llm_calls`、`sources` | 预算耗尽 / 正常 |

| P-001 | 点某条热点 | P-002 详情 | 携带 item_id；记录一次浏览 |

| P-001 | 点「更早」区条目 | P-002 详情 | 同上 |

| P-002 | 写备注并失焦 | P-002（已保存） | 自动保存，无弹窗 |
| P-002 | 点收藏 | P-002（已收藏） | 图标态变化 |
| P-002 | 校验未通过点「重试」 | P-002（加工中） | 消耗一次深加工配额 |
| P-003 | 点条目 | P-002 详情 | —— |
| P-003 | 取消收藏 | P-003（列表更新） | 需页面内二次确认 |

| P-004 | 点「测试代理」 | P-004（测试结果） | 只测连通性，不测能否访问特定站点 |

## 四、不做的东西（避免范围蔓延）

- 无登录页、无注册页、无个人中心。
- 无移动端布局。
- 无「分享」「导出 PDF」「生成报告」——v1 不出报告，只出条目。
- 无消息推送（站内角标即可）。
